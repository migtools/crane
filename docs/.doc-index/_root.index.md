# _ROOT Documentation Index

## Overview
This documentation area provides comprehensive guides, workflows, and reference materials for **Crane**, a tool designed for migrating Kubernetes workloads between clusters. It covers the end-to-end migration lifecycle, including resource extraction, multi-stage Kustomize-based transformations, validation, and compatibility constraints.

## Files Summary
* **pre-apply-validation-guide.md**: Provides a checklist and scripts for validating generated manifests against a target cluster before deployment.
* **plugins.md**: Explains the plugin system used for resource transformation, including discovery and management of built-in and community plugins.
* **resource-compatibility.md**: Outlines the functional requirements and RBAC context needed to migrate different Kubernetes resource types.
* **multistage-pipeline.md**: Provides an in-depth look at the multi-stage Kustomize pipeline, including CLI usage and stage chaining.
* **stateless-migration-quickstart.md**: A step-by-step tutorial for performing a basic stateless migration.
* **installation.md**: Instructions for installing the Crane binary from source or release.
* **README.md**: The main entry point for the documentation suite, providing an overview and links to all command references and concepts.

## Code Changes That Would Require Documentation Updates
* **Plugin System Changes**: Adding new built-in plugins, changing the plugin execution priority, or modifying how plugins are discovered/loaded.
* **CLI Command Updates**: Changes to flags, arguments, or the default behavior of `export`, `transform`, `apply`, or `validate` commands.
* **Pipeline Logic**: Changes to the sequential stage execution, Kustomize patch generation, or the "dirty check" file protection mechanisms.
* **File Structure**: Any modifications to the directory structure of `transform/`, `export/`, or the output format generated by `crane apply`.
* **Validation Logic**: Changes to how `crane validate` performs live or schema-based checks against target clusters.
* **Compatibility Scope**: Changes to which resource types Crane automatically handles versus skips, or changes to how owner references are calculated for migration.
* **Internal API**: Modifications to the `transform` or `apply` Go packages that affect how developers build custom pipeline integrations.

## Key Technical Concepts
* **Stages**: Sequential steps in the pipeline represented by directories (e.g., `<priority>_<plugin-name>`).
* **Kustomization**: The core tool used for applying patches and structuring resource groups.
* **Whiteout**: The process of excluding or filtering out specific resources during transformation.
* **JSONPatch**: The format used by plugins to clean/modify resources (removing `metadata.uid`, `status`, etc.).
* **Dirty Check**: A safety mechanism that prevents the accidental overwriting of manual edits in `transform/` directories.
* **Live Validation**: Checking compatibility against the target API server via `kubectl apply --dry-run=server`.
* **Namespace Renaming**: A high-impact operation requiring manual reconciliation of `ClusterRoleBinding` subjects and `NetworkPolicy` selectors.
* **Plugin Priority**: Numeric assignment controlling the sequence of transformation stages.

## Related Components
* **crane-lib**: The underlying library providing built-in Kubernetes plugins.
* **Kubernetes API Server**: The target for live validation and final resource application.
* **Kustomize (embedded)**: The engine used within `crane apply` for rendering manifests.
* **OperatorHub**: External dependency for migrating operator-managed workloads.
* **RBAC**: The permission context defining what resource scopes a user can export or migrate.
